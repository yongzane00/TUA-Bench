# H3 "Listen": wait for bash's completion signal (`terminus_2_harness3.py`)

H0 types a command, sleeps for the `duration` the model guessed (at most 60 s), then reads the
screen whether or not the command has finished. H3 installs a bash prompt hook (PROMPT_COMMAND).
Bash runs it each time a command finishes and the prompt returns, and the harness reads the
screen as soon as that happens (shaded). The wait is capped by `max_wait_sec` = 180 s.

Known bug: one exec both sends the keystrokes and waits, so its command line contains the
keystrokes. An agent's `pkill -f <pattern>` can match it and kill the harness's own wait.
The fix is pending.

```mermaid
sequenceDiagram
    autonumber
    participant H as Harness (H3)
    participant C as Container (bash in tmux)
    participant M as Main model
    participant G as Grader (tests)

    H->>C: start tmux shell
    rect rgba(15, 138, 128, 0.15)
        H->>C: install prompt hook (PROMPT_COMMAND)
        Note over C: not bash? stock H0 behaviour for the whole trial
    end
    H->>M: system prompt + task + first screen
    loop each turn
        M->>H: analysis, plan, keystrokes
        rect rgba(15, 138, 128, 0.15)
            H->>C: type keystrokes
            alt command ends with Enter
                C-->>H: prompt is back (ms for ls, minutes for a solver)
            else no prompt within 180 s
                Note over H: stop waiting, send the stock timeout message,<br/>skip the rest of this turn's commands
            else keys without Enter (C-c, q, input to a running program)
                Note over H: next prompt or the model's duration, whichever comes first
            end
        end
        C-->>H: screen text
        H->>M: screen text
    end
    M->>H: task_complete = true
    H->>M: "Are you sure?" + screen text
    M->>H: task_complete = true (confirms)
    H->>G: run tests on final env
    G-->>H: reward
```
